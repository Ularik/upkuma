ИНСТРУКЦИЯ ПО ПЕРЕНОСУ UPTIME KUMA НА UBUNTU SERVER

1. ИСХОДНАЯ СИСТЕМА
Uptime Kuma: 2.5.3
Node.js: 24.20.0
npm: 11.19.0
PM2: 7.0.4
Исходная ОС: Windows.

2. СОСТАВ РЕЗЕРВНОЙ КОПИИ
- data\ - база данных и пользовательские данные Uptime Kuma.
- uptime-kuma\ - исходный код Uptime Kuma 2.5.3 без node_modules и .git.
- server.js и monitor.js - отдельные копии модифицированных файлов.
- telegram-status-bot\ - код отдельного Telegram-бота.
- pm2-processes.json - справочная информация о прежних процессах PM2.
- versions.txt - версии программного обеспечения.

3. ВОССТАНОВЛЕНИЕ UPTIME KUMA
- Подготовить Ubuntu Server и установить совместимые версии Node.js и npm.
- Установить зависимости Uptime Kuma согласно package-lock.json.
- Разместить программу в постоянном каталоге сервера.
- Восстановить содержимое data\ в каталог данных Uptime Kuma.
- Проверить наличие и права доступа к базе данных kuma.db.
- Убедиться, что используются модифицированные server.js и monitor.js.
- Не заменять модифицированные файлы стандартными файлами из исходного релиза.
- Настроить запуск Uptime Kuma как системной службы.

4. ВОССТАНОВЛЕНИЕ TELEGRAM-БОТА
- Разместить telegram-status-bot в постоянном каталоге.
- Установить зависимости командой npm ci.
- Сохранить действующие настройки и секреты Telegram.
- Обеспечить подключение бота к локальному Uptime Kuma.
- Сохранить разрешённый ID группы Мониторинг сайтов.
- Проверить команду /status и принудительную проверку мониторов.
- Настроить автоматический запуск бота после перезагрузки.

5. TELEGRAM-УВЕДОМЛЕНИЯ
Необходимо сохранить:
- токен Telegram-бота;
- ID группы Мониторинг сайтов;
- шаблон {{ name}} - {{status}};
- привязку уведомлений ко всем мониторам.
Обеспечить исходящий доступ к api.telegram.org по TCP/443.
Проверить уведомления при переходах UP/DOWN.

6. СЕТЕВЫЕ НАСТРОЙКИ
- Назначить серверу постоянный IP-адрес или DNS-имя.
- Обеспечить доступ пользователей к веб-интерфейсу Uptime Kuma.
- Настроить межсетевой экран и необходимые правила доступа.
- Не публиковать панель управления в Интернет без защищённого доступа.

7. ПРОВЕРКА ПОСЛЕ ПЕРЕНОСА
- Проверить запуск Uptime Kuma.
- Проверить восстановление всех 44 мониторов.
- Проверить интервалы проверки 60 минут.
- Проверить настройки Telegram-уведомлений.
- Проверить получение UP/DOWN в группе.
- Проверить команду /status.
- Перезагрузить сервер и убедиться в автоматическом запуске обоих компонентов.

8. ВАЖНЫЕ ЗАМЕЧАНИЯ
- Не удалять и не изменять исходную Windows-установку до полного завершения проверки.
- Не запускать одновременно две копии с одинаковыми настройками уведомлений: это может привести к дублированию сообщений.
- pm2-processes.json содержит справочные Windows-пути и не предназначен для прямого импорта в Linux.
- Резервная копия содержит конфиденциальные данные, включая Telegram-токены и настройки доступа. Хранить её в защищённом месте.
- После успешного переноса проверить права доступа к файлам и каталогам.

ЦЕЛЬ:
Полностью восстановить Uptime Kuma 2.5.3 и отдельного Telegram-бота на Ubuntu Server с сохранением существующих мониторов, настроек, модификаций и уведомлений.
